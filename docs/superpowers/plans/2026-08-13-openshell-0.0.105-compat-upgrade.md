# OpenShell v0.0.105 Compatibility Upgrade Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make right-agent fully compatible with OpenShell v0.0.105 (CLI + gateway). Compatibility only — no adoption of new upstream features (stop/start, workspaces, endpoint-scoped credentials are follow-ups, see `docs/research/2026-08-13-openshell-0.0.105-upgrade-benefits.md`).

**Architecture:** The proto/gRPC adaptation is already implemented and verified on branch `chore/openshell-0.0.105-proto` (worktree `.worktrees/openshell-0105`, commit `c16ebc53`). What remains is one runtime break — the upstream 19-char sandbox-name cap — plus stale user-facing guidance referencing the removed `openshell gateway start` CLI.

**Background (verified 2026-08-13 against a live v0.0.105 gateway):**
- v0.0.86–0.0.90 added workspaces/services with DNS-routable names `workspace--sandbox--service`; each segment is capped at 19 chars (`MAX_ROUTABLE_NAME_LEN`, upstream `openshell-server/src/grpc/mod.rs`). 20 chars is rejected with `INVALID_ARGUMENT`, 19 accepted.
- Right's production names (`right-{agent}`, fallback `rightclaw-{agent}`) break for agent names >13 chars; test names (`right-test-shared-{label}-{runid}`, `right-test-{name}`) break almost always. Live evidence: 21/30 `ci_openshell_*` tests failed on master against v0.0.105, all on this single root cause.
- `openshell gateway start`/`destroy` no longer exist (removed v0.0.37); the gateway is a systemd user service. Right's diagnosis, doctor, and `right up` recovery text still reference them.
- Proto changes (workspace fields, `SandboxPhase` STARTING/STOPPING/STOPPED, Provider/ProviderProfile fields, `options.proto` import) are compile-time only and already fixed on the branch.

**Tech Stack:** Rust (edition 2024), tonic/prost, serde-saphyr, miette, nextest

### Task 2: 19-char sandbox naming

**Files:**
- Modify: `crates/right-openshell/src/openshell.rs` (`sandbox_name`, `resolve_sandbox_name`, ~lines 43–60)
- Modify: `crates/right-agent/src/init.rs:127-133`
- Test: `crates/right-openshell/src/openshell_tests.rs`, init test module

- [ ] **Step 1: Write failing tests for the naming helper**

```rust
#[test]
fn sandbox_name_fits_within_upstream_routable_limit() {
    assert_eq!(sandbox_name("agent-b"), "test-sandbox");
    let name = sandbox_name("fourteenchars1"); // right-{agent} would be 20 chars
    assert!(name.len() <= MAX_SANDBOX_NAME_LEN);
    assert!(name.starts_with("right-"));
    assert_eq!(name, sandbox_name("fourteenchars1")); // deterministic
    // common 8-char prefixes must not collide
    assert_ne!(sandbox_name("aaaaaaaaaaaaaaaa1"), sandbox_name("aaaaaaaaaaaaaaaa2"));
}
```

Run: `devenv shell -- cargo nextest run -p right-openshell sandbox_name_fits` → FAIL.

- [ ] **Step 2: Implement in `openshell.rs`**

```rust
/// Upstream cap on DNS-routable names (OpenShell v0.0.86+:
/// `workspace--sandbox--service` must fit a 63-char DNS label).
pub const MAX_SANDBOX_NAME_LEN: usize = 19;
```

`fit_sandbox_name(agent)`: use `right-{agent}` verbatim when ≤19; else `right-{first 8 of agent}-{hash4}` = 6+8+1+4 = 19, where hash4 = first 4 lowercase hex chars of SHA-256 of the full agent name. `sandbox_name()` calls it; `resolve_sandbox_name()` unchanged (explicit wins). `init.rs` emits `sandbox.name` via `sandbox_name(agent)` instead of inlining `right-{name}`.

Run: helper test → PASS; `init_agent_writes_explicit_sandbox_name_with_right_prefix` still PASS.

- [ ] **Step 3: Fail-fast validation for explicit names** — at agent config load, reject explicit `sandbox.name` longer than 19 with an error naming the upstream cap (Task 3's migration path rewrites instead of failing).

- [ ] **Step 4: Test-side naming** — `test_support.rs` shared sandbox: `right-test-shared-{label}-{runid}` → `rt-{label}-{runid}` (truncate to ≤19, e.g. `rt-io-3919500`). `TestSandbox::create` and `policy_apply.rs` `right-test-{name}` route through the same truncate+hash shape with an `rt-` prefix. Update the AGENTS.md "Shared test sandbox" paragraph.
