# Dashboard `build.rs`-driven frontend pipeline — Design Spec

**Date:** 2026-05-28
**Status:** Draft, awaiting review
**Author:** Brainstormed with Claude

## Goal

Move dashboard frontend compilation (`vite build`) into Cargo's build
phase via a new `build.rs` in `right-dashboard`. Eliminate
checked-in build artifacts (`crates/right-dashboard/static/`) — both
their git tracking and their Git LFS storage — so source and
embedded-bundle can never drift again.

## Motivation

`crates/right-dashboard/src/assets.rs` embeds
`crates/right-dashboard/static/dashboard/` at compile time via
`include_dir!`. That directory is a **checked-in build artifact**
(generated by `vite build`, then committed). The bundle lives in Git
LFS to keep the repo small.

This is fragile by construction: contributors who add or modify
frontend source files must remember to also run `npm run build` and
commit the regenerated assets. Forgetting this — as happened in commit
`a601262e` (which added `ProvidersView.vue` source but did not
regenerate the bundle) — produces a binary that compiles cleanly,
boots successfully, and silently serves a stale UI. The bug surfaces
only when an end-user notices a missing feature.

There is no test or CI guard against this. The same trap will recur
for every frontend change.

## Design overview

```
cargo build -p right
    │
    ├─▶ right-dashboard/build.rs runs
    │       ├─ cargo:rerun-if-changed for frontend sources
    │       ├─ Verify node + npm on PATH (hard fail with guidance)
    │       ├─ npm install (only if node_modules/ missing)
    │       ├─ npx vite build → $OUT_DIR/dashboard/index.html + assets/
    │       ├─ Verify $OUT_DIR/dashboard/index.html exists
    │       └─ exit 0
    │
    ├─▶ rustc compiles right-dashboard
    │       └─ include_dir!("$OUT_DIR/dashboard") embeds fresh bundle
    │
    └─▶ rustc compiles right (links right-dashboard)
```

Source-of-truth flips: the frontend source tree (`frontend/src/**`)
becomes the only authority. The bundled output lives only inside
`target/` and inside compiled binaries.

## Decisions captured during brainstorming

| Decision | Chosen option | Rationale |
|----------|---------------|-----------|
| Vite `outDir` | `$OUT_DIR/dashboard` | Canonical Cargo idiom. Working tree stays clean. `include_dir!` resolves `$OUT_DIR` at proc-macro time. |
| Run `vue-tsc` in build.rs? | No — CI only | Type errors surface in a dedicated CI job, not on every `cargo build`. Faster Rust builds. |
| Missing `node_modules/` | Auto-run `npm install` | Zero-friction first build. Cost paid once per workspace + once per CI cold cache. |
| Missing `node`/`npm` | Hard fail with actionable error | Honest and loud. Message points at `devenv shell`. |

## Components

### 1. `crates/right-dashboard/build.rs` (new)

```rust
use std::env;
use std::path::PathBuf;
use std::process::Command;

fn main() {
    let manifest_dir = PathBuf::from(env::var_os("CARGO_MANIFEST_DIR").unwrap());
    let frontend = manifest_dir.join("frontend");
    let out_dir = PathBuf::from(env::var_os("OUT_DIR").unwrap());
    let dashboard_out = out_dir.join("dashboard");

    // Rebuild triggers
    for path in [
        "frontend/src",
        "frontend/index.html",
        "frontend/vite.config.ts",
        "frontend/tsconfig.json",
        "frontend/package.json",
        "frontend/package-lock.json",
    ] {
        println!("cargo:rerun-if-changed={path}");
    }

    // Verify node + npm
    require_tool("node");
    require_tool("npm");

    // npm install (only if node_modules absent)
    if !frontend.join("node_modules").exists() {
        run("npm", &["install"], &frontend);
    }

    // vite build → $OUT_DIR/dashboard
    let mut cmd = Command::new("npx");
    cmd.args(["vite", "build"])
        .current_dir(&frontend)
        .env("VITE_OUT_DIR", &dashboard_out);
    run_command(cmd);

    // Sanity check: vite produced something
    let index = dashboard_out.join("index.html");
    if !index.exists() {
        panic!(
            "vite build completed but {} not found",
            index.display()
        );
    }
}

fn require_tool(name: &str) { /* which()-style check; print actionable error on miss */ }
fn run(prog: &str, args: &[&str], cwd: &std::path::Path) { /* spawn + check status + stream stderr */ }
fn run_command(mut cmd: Command) { /* shared implementation */ }
```

The actual code stays small (~80 LoC). No `[build-dependencies]` — only
`std::process::Command`.

### 2. `crates/right-dashboard/frontend/vite.config.ts`

```ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

const outDir = process.env.VITE_OUT_DIR ?? '../static/dashboard'

export default defineConfig({
  base: './',
  plugins: [vue()],
  build: {
    emptyOutDir: true,
    outDir,
    assetsDir: 'generated/assets',
    sourcemap: false,
  },
})
```

The fallback `'../static/dashboard'` is retained so manual `npm run build`
from inside `frontend/` still works when devs iterate without Cargo.
The static/ path will not exist in the working tree, but vite creates
it on the fly during dev iteration; this directory remains gitignored.

### 3. `crates/right-dashboard/src/assets.rs`

One-line change:

```rust
- static DASHBOARD_ASSETS: Dir<'_> = include_dir!("$CARGO_MANIFEST_DIR/static/dashboard");
+ static DASHBOARD_ASSETS: Dir<'_> = include_dir!("$OUT_DIR/dashboard");
```

`include_dir`'s macro expands environment-variable references at
proc-macro expansion time using the build script's environment, so
`$OUT_DIR` resolves correctly without further plumbing.

### 4. Git surgery

The `static/` directory is checked in AND has files in Git LFS.

**Files to git-rm (5 LFS-backed assets + 1 text index):**
- `crates/right-dashboard/static/dashboard/index.html`
- `crates/right-dashboard/static/dashboard/generated/assets/charts-C0wBuzb3.js`
- `crates/right-dashboard/static/dashboard/generated/assets/dist-CPrJONjh.js`
- `crates/right-dashboard/static/dashboard/generated/assets/echarts-BNmedilC.js`
- `crates/right-dashboard/static/dashboard/generated/assets/index-BXa5TH-A.css`
- `crates/right-dashboard/static/dashboard/generated/assets/index-CFcc0da6.js`

**`.gitattributes` lines to remove:**
```
crates/right-dashboard/static/dashboard/** linguist-generated=true
crates/right-dashboard/static/dashboard/generated/assets/** filter=lfs diff=lfs merge=lfs -text linguist-generated=true
```

**`.gitignore` additions:**
```
crates/right-dashboard/static/
crates/right-dashboard/frontend/node_modules/
```

(`node_modules/` likely covered by a top-level rule already — verify
during implementation; do not double-add. `frontend/dist/` is not
written by this design — vite writes to `$OUT_DIR/dashboard` under
Cargo, and to `../static/dashboard` under manual `npm run build`.)

**LFS storage cleanup:** `git rm` only removes pointers from the index.
The objects remain in the LFS store and are referenced by historical
commits — that is correct and expected. We do not rewrite history. New
clones will skip these objects (they are not reachable from `HEAD`),
but `git lfs pull` against historical refs will still fetch them. This
is acceptable; we are not trying to reclaim LFS storage, only to stop
adding new versions of these files.

### 5. CI workflows

**`.github/workflows/tests.yml` — no change.**
It runs inside `devenv shell` so it inherits `nodejs` from
`devenv.nix`. `cargo test --workspace` triggers `build.rs` which finds
node, runs npm + vite, and proceeds.

**`.github/workflows/build.yml` (release) — add setup-node step.**
The release job uses `dtolnay/rust-toolchain` directly, not devenv,
so it currently has no node. Add immediately after the protoc step:

```yaml
- name: Install Node.js
  uses: actions/setup-node@v4
  with:
    node-version: '20'
    cache: 'npm'
    cache-dependency-path: crates/right-dashboard/frontend/package-lock.json
```

setup-node's built-in npm cache keyed on the lockfile collapses the
~30-60s cold cost on warm runs. Node 20 matches the version pinned in
`devenv.nix` (verify exact version during implementation; bump if it
drifts).

**No new typecheck workflow in this spec.** Adding
`.github/workflows/frontend-typecheck.yml` (running `npm run typecheck`
on changes under `crates/right-dashboard/frontend/`) is recommended as
a follow-up but is out of scope for the minimum viable change.

## Error handling

| Scenario | Behavior |
|----------|----------|
| `node` not on PATH | `build.rs` panics with: `error: 'node' not found on PATH. Enter the devenv shell ('devenv shell') or install Node.js (>= 20).` |
| `npm` not on PATH | Same shape, swap `node` for `npm`. |
| `npm install` fails | Cargo build fails; npm's stderr is streamed to the cargo build log. |
| `vite build` fails | Cargo build fails; vite's stderr is streamed. |
| `vite build` succeeds but produces no `index.html` | `build.rs` panics. Defensive sanity check. |
| `include_dir!` cannot resolve `$OUT_DIR/dashboard` | Compile-time error from rustc. Should not happen if build.rs succeeded; if it does, indicates a build.rs bug. |

All errors are loud and stop the build. No silent fallback to an empty
bundle.

## Testing

### Unit / integration

- Existing `right-dashboard` and `right` test suites continue to pass.
  Build.rs runs implicitly on every `cargo test`.

### New regression test

Add a CI step in `tests.yml` (after the existing workspace test run):

```yaml
- name: Verify dashboard bundle contains expected views
  run: |
    devenv shell -- bash -c '
      set -euo pipefail
      cd crates/right-dashboard
      grep -r "ProvidersView" "$(cargo metadata --format-version=1 \
        --no-deps | jq -r ".target_directory")"/devenv/debug/build/right-dashboard-*/out/dashboard
    '
```

(Exact shape may vary — the principle is: after a real build, grep the
embedded-asset directory for a token that proves the latest frontend
source compiled in. Failing the build catches the exact stale-bundle
class of bug this design eliminates.)

### Manual smoke

1. `git clean -fdx crates/right-dashboard/`
2. `cargo build --release -p right`
3. Inspect `target/devenv/release/build/right-dashboard-*/out/dashboard/`
   for the expected `index.html` and `generated/assets/*`.
4. Run the binary; confirm `/providers` tab renders in the dashboard.

### Cold-checkout smoke

A fresh `git clone` + `cargo build --workspace` inside devenv shell
must succeed end-to-end. Document this in the spec; verify manually
once.

## Non-goals

- **TS typechecking in `build.rs`.** Deferred to a separate CI job.
- **LFS history rewrite.** Past commits retain their LFS pointers.
- **Hot-reload during development.** Devs use `npm run dev` from
  `frontend/` and point a browser at the Vite dev server.
- **Sourcemaps in production builds.** `sourcemap: false` retained.
- **WASM, SSR, or other runtime modes.** Static asset embedding only.

## Risks

- **Cold release CI builds slow by ~30-60s** (npm install). Mitigated
  by setup-node's npm cache keyed on `package-lock.json`. Warm runs
  add ~5s.
- **Devs outside devenv hit a hard error.** Acceptable: error message
  is explicit. Anyone using `nix-shell`, direnv, or a hand-rolled
  toolchain just needs node on PATH.
- **`include_dir!` re-evaluating on every build** can mildly slow
  incremental rustc when the proc-macro re-reads many files. In
  practice the embedded asset count is small (one HTML + a handful of
  JS/CSS files).
- **`vite build` is not perfectly deterministic across node versions.**
  Mitigated by setup-node pinning the major version. Output filenames
  contain content hashes, which is desirable for cache-busting.

## Migration steps (informational — implementation plan will own these)

1. Add `build.rs`, edit `vite.config.ts`, edit `assets.rs`.
2. `git rm` static/ contents + `.gitattributes` LFS lines.
3. Update `.gitignore`.
4. Add `setup-node` step to `build.yml`.
5. Verify `cargo build --workspace` from a clean checkout.
6. Verify the embedded bundle contains `ProvidersView` (smoke or new
   CI step).
7. Commit.

Implementation order matters: build.rs + vite.config + assets.rs all
land in one commit so the binary can still be built mid-PR. The git rm
of `static/` happens in the same commit. The CI workflow update can be
in a follow-up commit but should be in the same PR.
