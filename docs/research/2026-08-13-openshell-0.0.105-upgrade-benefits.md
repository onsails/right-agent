# OpenShell v0.0.56 → v0.0.105: benefits for right-agent

**Date:** 2026-08-13
**Method:** GitHub Releases API for every tag v0.0.57..v0.0.105 (all accounted for), proto
diff of vendored v0.0.62 vs v0.0.105, live verification against a v0.0.105 gateway on
`test-host` (docker driver, systemd user service).
**Companion plan:** `docs/superpowers/plans/2026-08-13-openshell-0.0.105-compat-upgrade.md`

## Verified live on this machine

- CLI + gateway v0.0.105 running as `openshell-gateway.service` (systemd user, docker driver).
- Sandbox create/exec/delete works end to end.
- Sandbox name cap confirmed empirically: 20 chars rejected (`name exceeds maximum length
  (20 > 19)`), 19 accepted.

## Breaking changes relevant to right-agent

| Change | Landed | Impact |
|---|---|---|
| Sandbox/provider/workspace names capped at 19 chars (`MAX_ROUTABLE_NAME_LEN`; `workspace--sandbox--service` must fit a 63-char DNS label, 19+2+19+2+19=61) | v0.0.86–0.0.90 (with workspaces/services) | `right-{agent}` breaks for agent names >13 chars; `right-test-shared-<label>-<runid>` test names break. 21/30 live `ci_openshell_*` tests failed on this alone. |
| `workspace` field added to most gRPC requests (empty = `default`); `all_workspaces` on list RPCs | v0.0.86–0.0.90 | Compile-only; fixed on `chore/openshell-0.0.105-proto`. |
| `SandboxPhase` gained `STARTING`/`STOPPING`/`STOPPED` + `StopSandbox`/`StartSandbox` RPCs | v0.0.105 | Compile-only for us; readiness logic must treat `STARTING` as not-ready. |
| `datamodel.proto` imports `options.proto` | v0.0.104 | Broke the vendor script (PR #147); script now fetches it. |
| GPU no longer inferred from image name; explicit `--gpu` required | v0.0.60 (#1835) | Only matters when right adds GPU agents. |
| Implicit policy authorization inheritance removed | v0.0.102 (#2499) | Re-validate `policy.yaml` semantics; policies must state intended access explicitly. |
| `gateway start`/`gateway destroy` CLI removed; gateway runs as a systemd user service / brew service | v0.0.37 (already past) | right's diagnosis/doctor text still says `openshell gateway start` — stale user-facing guidance, fixed in the compat plan. |

## Benefits worth adopting (post-compat, separate features)

1. **Endpoint-scoped static credentials (v0.0.103).** Proxy binds static provider credentials
   to their provider endpoint. Directly addresses the known limitation in ARCHITECTURE.md /
   onsails/right-agent#92: placeholder substitution is currently keyed by env-var name on
   *any* TLS-terminated endpoint. Highest-value security follow-up.
2. **Sandbox stop/start (v0.0.105, #2653).** Pause idle agents without deleting sandboxes —
   matches the "never delete sandboxes" rule while freeing host CPU/RAM. Requires treating
   `STOPPED` as a first-class state in the supervisor.
3. **Unchanged policy revision acknowledged (v0.0.103, #2557).** A no-op `policy set --wait`
   no longer pends forever — simplifies `wait_for_provider_composed*` polling.
4. **russh/jsonwebtoken/tar bumps (v0.0.100, #2617).** Reliability/security refresh of the
   exact stack under our SSH+tar file transfer. No API change; retest upload/download.
5. **TLS certificate hot-reload (v0.0.65, #1870).** Gateway rotates certs without restart.
6. **Server-side sandbox-delete conflict retries (v0.0.65, #1905).** Fewer delete failures
   during phase transitions.
7. **System CA root mode (v0.0.99, #2324).** Trust private/enterprise CAs in the
   TLS-terminating proxy without hand-managed bundles.

## New surface to evaluate later

- **Workspaces** (~v0.0.90): multi-tenant namespacing (`CreateWorkspace`, members, per-workspace
  providers). Could replace name-prefix isolation long-term; not needed for compat.
- **Services with browser-facing URLs** (`openshell service`, `service.proto` surface in
  `openshell.proto`): expose per-agent web UIs (dashboards, VNC) through the gateway with
  routable DNS names — this is the feature the 19-char cap exists for.
- **`compute_driver.proto` / VM driver**: pluggable compute backends (VM isolation instead of
  containers); v0.0.98 adds OTLP traces for the VM driver.
- **`credential_driver.proto`**: pluggable credential storage backends for providers.
- **`gateway_interceptor.proto`**: gateway-side request interceptors (e.g. TLS native roots,
  v0.0.102).
- **Windows gateway/CLI builds (v0.0.104)** and glibc-static supervisor libc (#2682) —
  packaging/portability only.
- **HA gateway reconciler lease (v0.0.62, #1577)** — multi-replica gateways; irrelevant for
  single-user local gateways.

## Fixes for known pain points

- v0.0.90 (#2416): internal allowed-IP proposals stay pending until applied — our hostless
  `allowed_ips` policy apply must keep polling policy status (already does).
- v0.0.57 (#1626): CLI respects gateway name for mTLS lookup — matters if we ever run
  multiple registered gateways.
- v0.0.57 (#1350): credential rotation tolerant of legacy over-length `provider.type` values.
- v0.0.70 (#1935): docker driver honors the configured supervisor image — enables pinning a
  custom supervisor.
- v0.0.58 (#1744): Kubernetes driver config passthrough (only if we revisit k3s).
