## The builder macro (read this first)

Almost every type/param uses the `apistruct!` attribute alias
(`src/macros.rs`):

```rust
#[derive(Clone, Debug, PartialEq, ::bon::Builder, ::serde::Serialize, ::serde::Deserialize)]
#[builder(
    on(Box<_>, into),
    on(ChatId, into),
    on(FileUpload, into),
    on(InputFile, into),
    on(InputMedia, into),
    on(InputMessageContent, into),
    on(String, into),
)]
```

bon 3.x semantics that matter for callers:

- **Required field** (type is not `Option<_>`): builder requires the
  setter, takes the field type by value. With `on(String, into)`, a
  `String` field setter takes `impl Into<String>` (so `&str` works).
  With `on(ChatId, into)`, a `ChatId` field setter takes `impl
  Into<ChatId>` → you can pass an `i64` (there is `From<i64> for
  ChatId`) or a `String`.
- **`Option<T>` field**: bon makes the setter **optional**. Unset →
  `None`. When set, `.field(x)` takes **`T`** (the unwrapped inner), NOT
  `Some(x)`. With `on(String, into)`, an `Option<String>` setter takes
  `impl Into<String>`. With `on(ChatId, into)`, an `Option<ChatId>`
  setter takes `impl Into<ChatId>` (e.g. an `i64`).
- `.build()` finalizes. `Type::builder()` starts.

Confirmed by frankenstein's own examples:
`SendMessageParams::builder().chat_id(message.chat.id).text("hello").reply_parameters(reply_parameters).build()`
— `chat_id` from `i64`, `text` from `&str`, the **optional**
`reply_parameters` set with the value directly (no `Some`)
(`examples/async_reply_to_message_updates.rs`).

## a. Client — `frankenstein::client_reqwest::Bot`

`src/client_reqwest.rs`:

```rust
#[derive(Debug, Clone, Builder)]
pub struct Bot {
    #[builder(into)]
    pub api_url: String,            // full URL incl. token; default api_url = BASE_API_URL + token
    #[builder(default = default_client())]
    pub client: reqwest::Client,
}
```

Constructors (all return **`Self`**, never `Result`):

- `Bot::new(api_key: &str) -> Self` — the normal path. Builds
  `api_url = "https://api.telegram.org/bot{api_key}"`
  (`BASE_API_URL = "https://api.telegram.org/bot"`, `src/lib.rs:46`).
- `Bot::new_url<S: Into<String>>(api_url: S) -> Self` — custom base URL
  (test servers, local mock).
- `Bot::builder()` — to inject a custom `reqwest::Client` (e.g. a client
  with our own timeouts / proxy). Default client has
  `connect_timeout = 10s`, `timeout = 500s`.

`Bot` is `Clone` (cheap — wraps an `Arc`-backed `reqwest::Client`).

There is NO deprecated `AsyncApi`/`Api` to worry about for our use — they
are zero-field deprecated shims (`src/lib.rs:48-59`).

## b. Response wrapper — `MethodResponse<T>`

`src/response.rs`:

```rust
pub struct MethodResponse<T> {
    pub ok: bool,                  // always true on success
    pub description: Option<String>,
    pub result: T,                 // <-- the payload
}
```

Extract payload with **`.result`**. Example:
`let user = bot.get_me().await?.result;`.

Every trait method returns `Result<MethodResponse<T>, Self::Error>`
(`Self::Error = frankenstein::Error` for the reqwest `Bot`).

## c. Trait — `frankenstein::AsyncTelegramApi`

`src/trait_async.rs`. The trait providing every Bot API call. The async
`Bot` implements it (`impl AsyncTelegramApi for Bot { type Error = Error; ... }`).
Bring it into scope: `use frankenstein::AsyncTelegramApi;` (re-exported at
crate root, `src/lib.rs:13`).

and the params type is `{$name:camel}Params`. So `editMessageText` →
`edit_message_text` + `EditMessageTextParams`.

## f. Error type — `frankenstein::Error`

`src/error.rs` (re-exported at crate root as `frankenstein::Error`):

```rust
#[derive(Debug, thiserror::Error)]
#[non_exhaustive]
pub enum Error {
    Api(ErrorResponse),                                  // API-level error (4xx/5xx body)
    JsonDecode { source: serde_json::Error, input: String },
    JsonEncode { source: serde_json::Error, input: String },
    ReadFile(#[source] std::io::Error),                  // local file open failed (multipart)
    HttpReqwest(#[source] reqwest::Error),               // transport / reqwest error
    // (WasmHasNoFileSupportYet, HttpUreq — not active for our non-wasm reqwest build)
}
```

- `Error` is `#[non_exhaustive]` — match with a `_ =>` arm.
- It is a `thiserror` enum and implements `std::error::Error` + `Display`,
  so `#[from] frankenstein::Error` works in our `thiserror` error types.

**Transport errors** are `Error::HttpReqwest(reqwest::Error)`.
`From<reqwest::Error> for Error` exists (`client_reqwest.rs:56`) — and it
strips the URL (token-bearing) via `.without_url()`. frankenstein
**re-exports reqwest** (`frankenstein::reqwest`). For
`TgError::Download(#[from] reqwest::Error)`: our download path will use
`reqwest` directly (file download from `api.telegram.org/file/...` is not
a frankenstein method), and `reqwest` is already a direct workspace dep of
`crates/bot` — so `#[from] reqwest::Error` is fine without adding anything.

**`retry_after` (429 handling)** — the path:

```

    ok: false,
    description: String,
    error_code: u64,
    parameters: Option<ResponseParameters>,
})
```
where (`src/response.rs:54`):
```rust
pub struct ResponseParameters {
    pub migrate_to_chat_id: Option<i64>,
    pub retry_after: Option<u16>,     // <-- u16
}
```

⚠ **Drift:** `retry_after` is **`Option<u16>`** — NOT `i64`, NOT `u64`.
Nested path:
`Error::Api(e).parameters.and_then(|p| p.retry_after)` → `Option<u16>`.
Also `error_code` is `u64`. `ErrorResponse` and `ResponseParameters` are
both at `frankenstein::response::*`.

Extraction sketch:
```rust
if let frankenstein::Error::Api(resp) = &err {
    if resp.error_code == 429 {
        let retry_after: Option<u16> =
            resp.parameters.as_ref().and_then(|p| p.retry_after);
        // ResponseParameters is Copy, so `resp.parameters` is Option<ResponseParameters>
    }
}
```

## Quick "gotchas" digest (the drifts vs. a naive mapping)

1. `edit_message_text` (and all `edit_message_*`, `*_live_location`,
   `set_game_score`) return `MethodResponse<MessageOrBool>`, not
   `Message`. Match `MessageOrBool::Message(Box<Message>)`.
2. `EditMessageTextParams.chat_id` is `Option<ChatId>`; its `reply_markup`
   is `Option<InlineKeyboardMarkup>` (bare, NOT `ReplyMarkup`).
   `SendMessageParams.reply_markup` is `Option<ReplyMarkup>` (wrap the
   keyboard).
3. `retry_after` is `Option<u16>` at
   `Error::Api(ErrorResponse).parameters: Option<ResponseParameters>.retry_after`.
   `error_code: u64`.
4. `CallbackQuery.from` is `User` (required, not Option);
   `CallbackQuery.message` is `Option<MaybeInaccessibleMessage>`
   (an enum, must match `MaybeInaccessibleMessage::Message(Box<Message>)`).
5. `UpdateContent` message-bearing variants are `Box<_>`:
   `Message(Box<Message>)`, `EditedMessage(Box<Message>)`,
   `CallbackQuery(Box<CallbackQuery>)`. `Update.update_id` is `u32`.
6. `Message.chat` is `Box<Chat>` (always present); `Message.from` is
   `Option<Box<User>>`; most media fields are `Option<Box<...>>`;
   `Message.photo` is `Option<Vec<PhotoSize>>`. `message_id` is `i32`.
7. Chat-type field is `Chat.type_field: ChatType` (serde `"type"`).
   `Chat.id` is `i64` but `User.id` is `u64`.
8. Media-send file field is typed `FileUpload`
   (`enum { String(String), InputFile(InputFile{path}) }`). Local file by
   path: pass a `PathBuf` (`From<PathBuf>` → `InputFile`). `&str` does not
   auto-convert; use `String` (→ file_id/URL) or `PathBuf` (→ upload).
9. `Bot::new(&str)` returns `Self` (infallible). Use `Bot::builder()` to
   inject a custom `reqwest::Client`.
10. Bring the trait into scope: `use frankenstein::AsyncTelegramApi;`.
    Payload is `MethodResponse::result`.
11. `ChatAction::Typing` etc. is `Copy`, `#[serde(rename_all = snake_case)]`.
12. `frankenstein` re-exports `reqwest` (`frankenstein::reqwest`); rustls
    is enabled by frankenstein's `client-reqwest` feature — no extra
    feature flag required.
